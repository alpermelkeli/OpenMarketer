1 · Brieffrom a person, the planner, the repository watcher or the orchestrator: platform, goal, and whether an image or research is wanted (yes, no, or let the plan decide); it may name an asset of the library to use
2 · Prepare code, no modelpin the approved profile version; build the writing context: live features with their evidence, voice, audience, do-not-mention, the platform's rules
Never in the writer's prompt
  • repository files, comments, issues
  • raw web pages: research comes back as quoted findings
  • features that are not live; credentials
3 · Plan writer structured outputdecides what this post needs before writing: the angle and the features it rests on, the format, research questions (at most three), and whether it needs an image (what it shows, the words on it). Code then holds the plan to the brief and the project: the brief's choices win; an image only where the platform takes one and the studio and its budget are available; only declared actions.
4 · Draft writerwrites the texts from the writing context, the plan and the findings, with no tools; each variant: text, angle, and claims naming the live features they rest on
Research run and wait: researcheronly if planned; findings come back as quoted, sourced data: they may shape the angle, never a claim
5 · Check code first, then a different model
Code rules hard
  • length as the platform counts it
  • no do-not-mention term
  • every claim names a live feature of the context
  • no link, no @mention; hashtag limit
  • numbers that are not in the profile are flagged
Critic criticreads each variant against the writing context: brand voice, facts, platform fit, and risky claims (legal, medical, financial, comparisons), which block a variant. Returns a structured report per variant with severity and edit suggestions, and ranks the variants that pass.

6 · Illustrate run and wait: creative studioonly if planned and no asset was named; after a text passed, so nothing is spent on text that fails. The request carries the image plan and its words. An asset comes back, or none: the post goes without it, or the run fails if the brief required one.
7 · Propose action publish_posteffect publishes: the gate holds the post with its image, the alternative texts, the claims with their evidence, the findings with their sources and all the reports
Revise writertakes the findings, or a person's note, and decides what to redo: the text (back to Draft), the image (back to Illustrate), or both. Rounds and cost are limited; at the limit the best variant that keeps every code rule and makes no risky claim goes on; if none, the run ends failed.
