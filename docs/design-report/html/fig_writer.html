3 · Plan writer structured outputdecides what this post says before writing: the angle, the features it rests on and the format. Code then holds the plan to the brief and the project: only live features, an announcement rests on its feature first, at most three; the plan asks for no action.
4 · Draft writerwrites the texts from the writing context, the plan and the brief's findings, to go with the brief's image, with no tools; each variant: text, angle, and claims naming the live features they rest on. Findings may shape the angle, never a claim
5 · Check code first, then a different model
Code rules hard
  • length as the platform counts it
  • no do-not-mention term
  • every claim names a live feature of the context
  • no link, no @mention; hashtag limit
  • not just the words on the image repeated
  • numbers that are not in the profile are flagged
Critic criticreads each variant against the writing context: brand voice, facts, platform fit, and risky claims (legal, medical, financial, comparisons), which block a variant. Returns a structured report per variant with severity and edit suggestions, and ranks the variants that pass.
